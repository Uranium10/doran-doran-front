# 책 뷰어·진입 화면 복귀 명세 (2026-09-17, v2)

## 책의 순서

1. 첫 화면: 왼쪽은 비우고 오른쪽에 앞표지·제목·표지 그림을 둔다.
2. 데스크톱: 장면 첫 펼침의 왼쪽에 삽화 한 장, 오른쪽에 해당 장면의 첫 본문을 둔다.
3. 이어지는 펼침: 양쪽 모두 본문이다. 삽화는 반복하지 않는다. 새 장면은 새 펼침에서 시작한다.
4. 장면의 마지막 본문 쪽이 홀수면 반대쪽은 빈 종이다. 다른 장면을 억지로 섞지 않는다.
5. 마지막 본문을 넘기면 왼쪽 뒷표지, 오른쪽 완료 안내와 버튼이 나온다.
6. 퀴즈가 있는 신규 동화는 '문제 풀러 가기', 읽기 전용/퀴즈 없는 동화는 '돌아가기'다.

모바일은 같은 순서의 종이를 한 쪽씩 표시한다. 장면 삽화 한 쪽 다음에 본문 쪽들이 이어진다.
끝 화면에서는 작은 뒷표지와 완료 안내를 상하로 배치한다.

## 크기와 조작

- 사이트 헤더 64px 아래 전체 높이를 쓴다. 펼친 책의 가로:세로는 1.42:1이며 한 쪽은 0.71:1인 세로형이다.
- 컨테이너의 실제 너비와 높이를 모두 고려해 책 크기를 정한다. 작은 높이에서는 최소 읽기 높이를 보장해 세로 스크롤을 허용한다.
- 컨트롤은 왼쪽 사이드 리모컨에 모았다: 이전 화면, 이전/다음 장, 현재 위치, 글자 크기, 처음부터, 전체 화면.
- 종이 클릭/가로 드래그/방향키 이동을 지원한다. Home/End는 앞/뒷표지다. 마지막 화면의 실제 버튼은 페이지 넘김과 구분한다.
- 620ms 종이 앞뒤 회전 애니메이션을 유지한다. 감소된 모션 설정에서는 즉시 이동한다.
- 회전하는 복제면은 aria-hidden과 inert로 감춰 화면 읽기/키보드 초점에 중복으로 나타나지 않는다.

## 페이징과 데이터 흐름

`API pages[] → useReadingPages(실제 종이의 본문 영역 측정) → paginateStory(원문 분할)
→ buildBookSpreads(표지/삽화/본문/빈 종이/뒷표지 배치) → PopupBook`

- 표지를 보고 있을 때도 숨은 본문 종이로 정확한 높이를 측정한다.
- 글꼴·크기·화면 변화 뒤 sceneIndex/startOffset/endOffset으로 읽던 위치를 찾는다. 앞/뒷표지를 보고 있었다면 표지를 유지한다.
- 글꼴 알림이 와도 분할 결과가 같으면 배열을 재생성하지 않아 진행 중인 넘김을 불필요하게 취소하지 않는다.
- 원문/공백/개행과 장면 이미지 URL은 변경하지 않는다. 그림은 object-fit:contain으로 전체 표시한다.
- 새 유료 이미지 생성은 없다. 표지 URL이 없는 과거 동화는 첫 장면 이미지를 표지에만 폴백한다.

## 돌아갈 화면

| 진입 경로 | 책 리모컨의 이전으로 / 최종 단계 완료 |
|---|---|
| 대시보드에서 생성 동화 열기 | 대시보드 홈 뷰 |
| 생성 동화 퀴즈 결과 화면의 이전으로 | 대시보드 홈 뷰 |
| 라이브러리에서 저장 동화 열기 | 라이브러리 목록(보기 방식 유지) |
| 공개 전래동화 열기 | 랜딩 페이지의 전래동화 목록 /#library |

브라우저 history.back()을 이용하지 않고 명시적인 콜백/경로를 쓴다. 완료한 퀴즈나 로그인 화면으로 잘못 돌아가지 않게 하기 위함이다.
보관함 재열람은 기존 정책대로 읽기 전용이며, 퀴즈 재채점 기능을 새로 추가하지 않았다.
퀴즈 진행 중 '동화 다시 보기'는 유지한다. 최종 결과의 이전으로는 퀴즈로 돌아가지 않는다.

## Storage

이미지는 기존 `covers/{story_id}/cover.jpg`, `covers/{story_id}/page-N.jpg` 경로를 계속 쓴다(확장자는 형식에 따라 다름).
서버 pages[]는 장면 단위이고 화면의 종이 수와 다르다. 장면별 URL과 저장 방식, API 스키마는 변경하지 않았다.

## 2026-09-17 추가 보완: 안내·장 제목·표지 점멸·직접 이동

- 넘김 안내는 앞표지의 왼쪽 바깥 공간에만 표시한다. 모바일은 왼쪽 공간이 없으므로 표지 바로 위에 표시한다. 넘김 중에는 안내를 숨긴다.
- 삽화와 제목을 figure/figcaption으로 묶고 그림 바로 아래에 제목을 둔다. 삽화 위/본문 아래의 장 번호는 `1장`처럼 표시한다.
- 표지 왼쪽 공간은 `outside`, 본문 끝의 실제 빈 종이는 `blank`로 구분한다. 이전에는 `right.kind === cover`일 때만 왼쪽 배경을 숨겨, 넘김 중 고정면 조합이 바뀌면 흰 종이가 잠깐 나타났다. 이제 outside 자체가 항상 투명하므로 여닫기 양방향에서 점멸하지 않는다.
- 리모컨 번호 입력 후 Enter 또는 이동 버튼으로 직접 이동한다. 번호는 현재 리모컨의 본문 펼침 기준(데스크톱 두 쪽, 모바일 한 쪽)이며 앞/뒷표지는 제외한다.
- 유효 범위는 `1..전체 본문 펼침 수`. 음수/0은1, 초과 값은 마지막으로 제한하고 소수는 버린다. 빈 입력/문자는 현재 번호로 복원하며, Escape는 편집을 취소한다. 재분배 후 번호와 전체 수는 함께 갱신한다.
- API/서버/DB/환경변수 변경 및 유료 호출 없음.
- 검증: 배치/페이징/생성 상태 테스트, TypeScript, production build. 실제 데스크톱/모바일에서 안내/제목/직접 이동/범위 제한을 확인하고, 표지를 여닫는 중 고정 왼쪽 면의 배경 rgba(0,0,0,0)·그림자 none을 확인했다.

## 2026-09-17 전체 삽화 사전 준비 및 넘김 스크롤바 흔들림 수정

### 이미지 준비

`PopupBook → useBookImages → preloadBookImages → 준비 완료 → PreparedBook`

- 생성 동화·보관함·공개 전래동화 모두 API 데이터를 받은 뒤 같은 공통 준비 단계를 거친다.
- cover_image(없으면 첫 컷)와 모든 pages[].image URL을 중복 제거한 후 병렬 다운로드한다. Image.decode까지 기다려 첫 표시 시 해석 지연을 줄인다.
- 준비 중에는 진행 개수와 '그림들을 책 속에 담고 있어요' 화면, 이전으로 버튼을 표시한다. 그림이 없는 책은 바로 표시한다.
- 각 URL은 다운로드/디코딩을 합쳐 최대15초 기다린다. 오류·디코딩 실패·시간 초과는 해당 컷을 대체 안내로 표시하고 나머지 동화는 읽을 수 있게 한다. 실패 URL을 넘김 때마다 재요청하지 않는다.
- 읽는 동안 준비한 Image 참조를 유지한다. 브라우저 캐시·디코딩 재사용을 돕는 방식이며 기기 메모리 압박에 따른 브라우저의 캐시 정리까지 막는 것은 아니다.
- 다른 동화로 바뀌거나 화면을 떠나면 이전 요청의 이벤트/타이머를 정리하고 늦은 완료는 반영하지 않는다. URL이 바뀌면 새로운 준비 상태로 전환한다.
- API 응답·Storage URL·DB는 변경하지 않는다. 브라우저에서 내려받는 시점을 앞당기는 프론트 수정이다.

### 넘김 중 흔들림

- 3D로 회전하는 종이의 투영 영역이 뷰어 밖으로 나가 문서 스크롤 크기를 늘릴 수 있었다. 스크롤바 등장 → 가용 폭 변화 → 재페이징과 화면 흔들림으로 이어질 수 있다.
- reader에 overflow:clip을 적용해 애니메이션의 시각적 넘침을 뷰어 안으로 제한했다. body의 스크롤을 강제로 잠그지 않으므로 짧은 화면의 정상 스크롤·본문 내부 스크롤은 유지한다.

### 검증

- 사전 준비 테스트: URL 중복 제거, 전 이미지+decode 완료 대기, 캐시, 네트워크/디코딩 실패, 시간 초과, 이탈 취소/늦은 콜백 통과.
- 기존 book-layout/story-pagination/generation-controller 테스트, 별도 TypeScript, production build 통과.
- 실제 브라우저에서 느린 이미지 준비1/3 → 표지 열림, 404 컷 대체 안내 확인.
- 데스크톱 넘김800ms 중19회 측정: 문서/가용 화면1440×900 고정. 모바일20회 측정:390×844 고정. 두 측정 모두 넘김 진행/완료 상태를 포함했다.
- 임시 이미지 지연 API/테스트 화면은 배포 전 제거했다. 유료 API 호출 없음.

## 최신 모바일 배치 — 하단 리모컨 (2026-09-17)

이 절은 위의 모바일 좌측 리모컨/책 바깥 제목/표지 위 안내 규칙을 대체한다. 데스크톱은 기존 좌측 리모컨을 유지한다.

- 767px 이하에서 뷰어를 책 영역 + 하단 도구막대 두 행으로 배치한다. 헤더 바로 아래10px부터 책을 표시한다.
- 책 바깥 제목 줄과 별도 넘김 안내를 숨긴다. 표지 자체의 제목과 펼치기 안내, 본문 속 장 제목은 유지한다.
- 모바일 책은 남은 가로·세로를 채운다. 고정된0.71 비율 때문에 생기던 큰 위아래 여백을 없앤다. 본문은 실제 높이·너비로 다시 분할한다.
- 하단에는 이전 화면/이전 장/페이지 번호 및 확인 아이콘/다음 장/설정 아이콘을 둔다. 설명 텍스트는 숨기되 aria-label은 유지한다.
- 글자 크게·작게/처음부터/전체 화면은 설정 아이콘으로 펼친다. 페이지 이동을 시작하면 설정 메뉴를 닫는다. 데스크톱에서는 해당 도구가 항상 기존 위치에 표시된다.
- 하단 safe-area-inset-bottom을 반영해 기기 홈 영역과 겹치지 않게 한다. 전체 화면에서도 같은 배치를 쓴다.
- 실제390×844에서 책370×692, 하단 도구막대 높이약56px. 320×568에서도 도구막대/설정 메뉴가 잘리지 않고 문서 넘침 없음. 글자 확대 및 페이지 번호 이동 확인.
- 1440×900에서 기존76px 좌측 리모컨 유지 확인. 모바일 넘김 중에도 문서 크기390×844 고정. TypeScript/production build 및 배치·페이징 테스트 통과.
- API/백엔드/DB/환경변수 변경 없음.
